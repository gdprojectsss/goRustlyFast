# Area 2: startup, command line flags and the shell environment

### Added

- bash style command line options: option clusters such as `-lc`, `-ilc`, `-ec` and `-euxo pipefail`, `-o name` and `+o name`, `-O name` and `+O name` for `shopt`, the `set` letters `-abefhkmptuvxBCEHPT`, `-s` to read commands from standard input with positional parameters, `-n` to check syntax without running anything, `--norc`, `--noprofile`, `--rcfile file` (also `--init-file`), `--verbose`, and `--posix` and `--noediting`, which are accepted and ignored. `--` and `-` end the options, and the command string of `-c` is the first argument after all options, as in bash. Unknown options print the usage and exit with status 2.
- Shell variables `UID` and `EUID` (read only), `BASHPID`, `EPOCHSECONDS`, `EPOCHREALTIME`, `SRANDOM`, `GROUPS`, `HOSTNAME`, `OSTYPE`, `HOSTTYPE`, `MACHTYPE`, `PS4` (default `+ `) and `GRFSH_VERSION`. Values inherited from the environment are kept. `BASH_VERSION`, `BASH_VERSINFO` and `BASH` stay unset on purpose: grfsh is not bash, and scripts that check for them should take their portable path or start bash.
- `SHLVL` is incremented and exported at startup.
- `shopt expand_aliases` and `shopt login_shell`.

### Fixed

- `grfsh -l -c command`, `grfsh -lc command`, `grfsh -l script` and shells started with an argv[0] beginning with `-` now read `~/.grfsh_profile` and add `/etc/paths` to `PATH`, so editors and GUI apps that resolve the environment with `-ilc` or `-lc` get the login `PATH`.
- `~/.grfshrc` is read by interactive shells only: `grfsh -i -c command` reads it, and `echo command | grfsh` no longer does, as in bash.
- `grfsh -i` with standard input that is not a terminal hung; it now runs without job control.
- When `PATH` is unset, grfsh uses `/usr/local/bin:/usr/local/sbin:/usr/bin:/usr/sbin:/bin:/sbin`.
- With `HOME` unset, `~` expands to the home directory from the user database.
- `$0` is the name grfsh was started with, so a login shell started as `-grfsh` reports `-grfsh`, and `grfsh -c` without a name reports the shell's path, as bash does.
- The `ls` and `grep --color=auto` aliases exist only in interactive shells, and non-interactive shells expand aliases only after `shopt -s expand_aliases`, as in bash. Scripts and `-c` commands no longer see the aliases, and `type ls` in a script reports the command.
- `-c` commands run line by line, so an alias or `shopt` set on one line applies to the next.
- `--json` now also produces a JSON result for commands read from standard input, `--check` and `--explain`.
- The warning about an unsafe startup directory is printed once instead of once per startup file.
- `cd ..` from a deleted directory reports that the current directory can no longer be found and sets `PWD` to the path it was given, as in bash, instead of a directory that does not exist.

## Notes for the integrator (docs)

- docs/grfsh.1 OPTIONS: document the new options listed above (`-s`, `-n`, `-o`/`+o`, `-O`/`+O`, the `set` letters, `--norc`, `--noprofile`, `--rcfile`, `--init-file`, `--posix`, `--verbose`, `--`, `-`), and that `-c` takes its command from the first argument after the options. `-h` alone still prints help; inside a cluster `h` is the `set -h` letter.
- docs/grfsh.1 STARTUP FILES: replace "Shells that read commands from a terminal or standard input then run ~/.grfshrc" with "Interactive shells (a terminal, or `-i`, including `-i -c`) then run ~/.config/grfsh/grfshrc or ~/.grfshrc, or the file given with `--rcfile`". State that login shells read the profile also with `-c` and with a script, and that `--noprofile`/`--norc` skip the files. An interactive login shell reads the profile and then the rc file (unlike bash, which reads only the profile).
- README line 294: "`~/.grfshrc` ... runs on startup" should say "runs when grfsh starts interactively".
- Compatibility page (grf.sh/docs/compatibility): add a "Shell variables" note: grfsh sets `GRFSH_VERSION` and does not set `BASH_VERSION`, `BASH_VERSINFO` or `BASH`. Scripts commonly test `[ -n "$BASH_VERSION" ]` to decide whether bash features are available, and many re-exec bash when it is missing; claiming to be bash would make them use features grfsh may not support, so leaving them unset is the safe outcome. Scripts that want to detect grfsh can test `$GRFSH_VERSION`.
- Compatibility page: aliases follow bash: non-interactive shells expand them only after `shopt -s expand_aliases`.
- Compatibility page: the default `PATH` used when `PATH` is unset does not include `.` (bash's built in default ends with `.`), and grfsh exports it.
- The `shopt` line in src/builtins/help.rs ("glob options: ...") could mention `expand_aliases` and `login_shell`; left unchanged to avoid a conflict with area 6.
