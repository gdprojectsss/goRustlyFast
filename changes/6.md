### Added

- The `let`, `builtin`, `caller`, `enable` and `compgen` builtins. `caller` takes a frame number, `enable -n` turns a builtin off and `enable` lists them, and `compgen` supports `-a -b -c -d -e -f -k -u -v`, `-A action`, `-W`, `-G`, `-X`, `-P` and `-S`.
- `type -t`, `-p`, `-P`, `-a` and `-f`, shell keywords in `type` and `command -v`, `command -V`, and `command -p`, which looks the command up in the default `PATH`.
- `declare -f` and `type` print function definitions in the same layout as bash, so `eval "$(declare -f name)"` recreates a function. `declare -F name` prints only the name.
- `cd -P`, `cd -L`, `cd -e`, `pwd -P` and `pwd -L`. `pwd -P` resolves symbolic links, so `cd /tmp; pwd -P` prints `/private/tmp` on macOS. `set -P` makes both physical by default.
- `set -f` (`noglob`), `set -C` (`noclobber`) with `>|` to overwrite anyway, `set -v` (`verbose`), `set -n` (`noexec`, ignored in interactive shells), and the other `set` letters and `-o` names bash accepts, including `posix`. `set -o` and `set +o` list every option, and `$-` shows the same letters as bash.
- `shopt` knows every bash 5.3 option and accepts `-p`, `-q`, `-o` and combinations such as `-qo`. `nocasematch`, `failglob` and `lastpipe` work, besides the globbing options. Options grfsh does not act on yet are accepted and remembered.
- `source` and `.` look for a name without a slash in `PATH` first and then in the current directory, like bash (`shopt -u sourcepath` turns that off), and accept `-p path`. This makes `git-sh-setup` and the git commands written in shell work.
- `printf` supports `%(format)T` dates, `%a`, `%Q`, length modifiers such as `%ld`, `-v` with array elements and associative keys (`printf -v 'map[key]' ...`), negative `*` widths (left justified) and negative `*` precisions (ignored). `%q` quotes like bash, with backslashes and `$'...'` for control characters.
- `mapfile` and `readarray` accept `-d delim` (including `-d ''`), `-O origin`, `-u fd`, and `-C callback` with `-c quantum`.
- `read -N`, `read -u fd`, and `read -e` and `-i` (accepted, no line editing). `read -n` counts characters, not bytes, so `read -n 2` keeps two accented letters.
- `umask` accepts symbolic modes such as `u=rwx,g=rx,o=` and `g+w`, and `-p`.
- `help` entries for `time`, `let`, `builtin`, `caller`, `enable` and `compgen`.

### Fixed

- `printf '%d' 3.7` prints `3` with an `invalid number` error and status 1, like bash, instead of `0`. Hex and octal errors and numbers out of range are reported the way bash reports them.
- `printf` with a huge `*` width or precision reports `Result too large` instead of running for a long time and using gigabytes of memory, and a huge literal width stops with an error.
- An unknown `printf` conversion stops with `invalid format character`, and `%` at the end of the format reports `missing format character`.
- `read -p` shows the prompt only when reading from a terminal, `read` with no names keeps leading and trailing blanks in `REPLY`, and `read -t 0` reports whether input is ready. Invalid `-n` counts and file descriptors return status 1.
- A `set -u` error in `grfsh -c` exits with status 127, as in bash 5.3; scripts still exit with 1.
- `**` with `globstar` also matches the directory itself (`dir/**` includes `dir/`), as in bash.
- `local` outside a function fails with status 1 (now covered by the bash comparison suite).
- `help` points to https://grf.sh/docs/ and shows `timeout --preserve-status` and `files [-a] [-r] [path...]`.
