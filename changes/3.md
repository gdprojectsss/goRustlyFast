### Added

- `select` menus, with `PS3`, `REPLY` and the same column layout as bash.
- `coproc` and `coproc NAME { ...; }`, with the `NAME` array of file descriptors and `NAME_PID`.
- Extended glob patterns `@(...)`, `?(...)`, `*(...)`, `+(...)` and `!(...)`: always inside `[[ == ]]`, and after `shopt -s extglob` in file names, `case` and `${x##pattern}` style expansions.
- `|&` pipes standard error together with standard output.
- Named file descriptors: `exec {fd}>file`, `{fd}<file`, `{fd}>&-` and `{array[1]}>&-` pick a free descriptor from 10 up and store it in the variable.
- `[[ -o option ]]` and `[ -o option ]` test shell options.
- The arithmetic comma operator, as in `for ((i = 0, j = 10; i < j; i++, j--))`, array elements in arithmetic (`(( a[i]++ ))`, `$(( m[key] * 2 ))`), and variables whose value is a name or an expression are evaluated like bash does.
- `$"..."` strings work like `"..."`.

### Fixed

- After a syntax error, grfsh no longer runs the body of the broken command. Like bash, a script or `-c` command stops with status 2, and `eval` or `source` return 2 to the caller.
- Blank lines inside here-documents and multi-line strings were dropped when running a script file or `source`.
- Long scripts are parsed in linear time: a 4000 line function took 11 seconds and a 100,000 line here-document more than a minute, both now take a fraction of a second.
- `${x//pattern/replacement}` and the other pattern operators are fast on long strings: replacing in a 10KB string took more than 30 seconds.
- `case` inside `$( )`, comments containing `)` inside `$( )`, and `$((cmd) | (cmd))` are parsed correctly.
- `[[ ... && (( a ) || ( b )) ]]` with nested groups no longer fails with "expected '))'".
- `! ! command` negates twice instead of running a command called `!`.
- Arithmetic follows bash: `&&`, `||` and `?:` skip side effects and errors in the branch that is not taken, `"3" + 4` works, `08` is an error ("value too great for base") also in `[[ 08 -eq 8 ]]`, `[[ 1+1 -eq 2 ]]` evaluates both sides, `1 ++ 2` is 3, and a variable that refers to itself is a "recursion level exceeded" error.
- A division by zero or other error in `$(( ))` stops only the current command line, like bash, instead of the whole script.
- Deeply nested commands, substitutions, `${x:-...}` words, arithmetic and `source` or function recursion report "maximum nesting depth exceeded" instead of crashing the shell.
- A here-document that reaches the end of the file without its terminator prints bash's warning and keeps its text instead of failing.
- Carriage returns in scripts with Windows line endings are kept as ordinary characters, as bash does, instead of being silently removed.
- Quoted characters in patterns, such as `[[ $x == "@(a)" ]]`, always match literally.

### Notes for the integrator

- Docs: README compatibility notes should drop `select`, `coproc`, extended globs, `|&`, named file descriptors and `[[ -o ]]` from any "not supported" lists. `shopt` now also accepts `extglob` (help text updated).
- `src/check.rs`: the `UNSUPPORTED_COMMANDS` entries for `coproc` and `select` and the `UNSUPPORTED_TEXT` entry for `shopt -s extglob` (and the `syntax_errors_and_text_patterns` test that expects it) should be removed; `select` and `coproc` now parse as their own commands, so the command entries no longer fire anyway.
