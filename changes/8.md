### Fixed

- `where column =~ pattern` and `!~` match an extended regular expression, as documented, instead of a case-insensitive substring. Start the pattern with `(?i)` to ignore case. `has` and `lacks` keep the old substring match.
- `where` and `search` translate `\d`, `\w`, `\s`, `\b` and `\D`, `\W`, `\S` the same way on macOS and Linux, so `search '\d+'` no longer matches a literal `d` on macOS, and an invalid pattern is reported instead of matching nothing.
- `git-status` paths are relative to the current directory, so `git-status | where state == modified | get path | xargs git add` works from a subdirectory.
- Tables shown on a terminal, written as plain text, markdown or html show control characters as `\e`, `\n`, `\x07` and similar escapes, so a file name cannot send terminal escape sequences.
- `load` strips a UTF-8 byte order mark, keeps extra CSV fields as new columns instead of dropping them, reads files that are not valid UTF-8, and names the line of a bad JSONL line.
- `where size -gt abc` is an error instead of matching nothing, and `and` or `or` inside a value, as in `where 'name == rock and roll'`, no longer splits the condition.
- `ports` shows full process names and says when it is not running as root, since it can then only see some owners.
- Unknown flags and usage errors of table commands, such as `git-status -x`, `procs -x` and `ports -a`, exit with status 2.
- File errors from `files`, `load` and `search` read "No such file or directory" without "(os error 2)".
- `--serve` requests read standard input from `/dev/null` instead of the server's own input, and a request timeout also stops a builtin `read` that is waiting.
- `write-file` refuses to replace a file with empty input, which usually means a missing pipe. `write-file -f` writes an empty file on purpose.
- `--serve` removes its socket when stopped with SIGTERM, SIGHUP or SIGINT, a socket path that is too long gets a readable message, and `--client -t` says when the request timed out or the busy server did not answer.
- Agent output logs older than a day are removed when agent mode starts.
- `explain` shows `x=$(date)` as `sets x="$(date)"` instead of a literal string, uses aliases defined on earlier lines, and explains that an alias defined on the same line does not apply yet.
- `replace` matches text with LF line endings in CRLF files and keeps the CRLF endings, and a `<<<<<<<` block with an empty new side deletes the old lines instead of leaving an empty line.
- `--check` stops at a top-level `exit` or `exec` like bash, so installers with a payload after `exit` pass. It follows `source` and `.` of literal and script relative paths for functions, stays quiet about unknown commands when a sourced file cannot be found, reports a top-level call to a function defined further down, accepts calls inside functions to functions defined later, accepts commands guarded by `command -v` and zsh only commands behind a zsh check, and no longer reports `hash`.
- `--check` names unsupported features it used to miss or report as plain syntax errors: `select`, `trap ... DEBUG` and `RETURN`, `declare -n`, `set -a`, `set -f`, `printf '%(...)T'`, `BASH_VERSINFO`, `BASH_LINENO` and every line with an extended glob. An unclosed quote is reported on the line where it starts, and scripts that are not valid UTF-8 are checked.
- Startup files and plugins are refused when a directory they live in, including the directories a symlink points into and every parent of a plugin, is writable by other users.

### Added
