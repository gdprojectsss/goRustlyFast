### Added

- The `fc` builtin: `fc -l` lists history (`-n` without numbers, `-r` reversed, ranges by number, offset or prefix), `fc -s old=new command` runs a command again with a change, and plain `fc` opens commands in `$FCEDIT`, `$EDITOR` or `vi` and runs what you save.
- History expansion understands `^old^new`, word designators (`!!:0`, `!!:2`, `!!:1-3`, `!!:2*`, `!!:-2`, `!$`, `!^`, `!*`), `!?text?`, `!#` and the modifiers `:h`, `:t`, `:r`, `:e`, `:p`, `:q`, `:x`, `:s/old/new/`, `:gs/old/new/` and `:&`.
- Alt-. inserts the last argument of the previous command, and pressing it again walks back through older commands. Ctrl-E and End accept the whole autosuggestion, Alt-F accepts its next word.
- `$COLUMNS` and `$LINES` are set in interactive shells and follow window size changes.
- `HISTSIZE`, `HISTFILESIZE` and `HISTFILE` are honoured. History keeps 50000 entries by default.
- Sourcing a zsh or bash startup file such as `~/.zshrc` prints one hint explaining that zsh or bash only lines will fail and where to put grfsh settings.

### Fixed

- History was capped at 100 entries and the file was cut down to 100 lines. It now keeps 50000 entries by default and never truncates a larger file below the limit.
- History is written as each command is accepted, merged under a file lock, instead of rewriting the whole file at exit. Several shells open at once no longer overwrite each other's history, and a killed shell no longer loses its session.
- After Ctrl-C interrupted `read`, `read -s`, a command substitution or `configure-prompt`, the next command typed was silently dropped.
- The git status in the prompt never delays commands: pressing Enter no longer waits for `git status`, git is not run outside repositories, the status is refreshed after every command (so `git switch` and `git add` show at once), and a status that arrives late redraws the prompt while nothing has been typed yet.
- Several lines arriving at once at the prompt, from typing ahead while a command runs or from a paste without bracketed paste, all run instead of only the first.
- Ctrl-D with stopped or running jobs warns first, like `exit`, instead of leaving at once, and prints `exit`.
- Tab completion lists the candidates and completes their common prefix instead of silently picking the first one. Exact case matches win (`/us` completes to `/usr`, not `/Users`), hidden files are offered only for a `.` prefix, `$VAR` and `~` in paths are completed, and a unique completion adds a space or closes its quote.
- Ctrl-Z on a loop such as `while true; do sleep 1; done` stops the current command and returns to the prompt instead of starting a new stopped job on each press. Jobs killed by a signal are reported as `Killed`, `Terminated` and so on instead of `Exit 137`.
- Terminal settings are restored when a command at the prompt is killed or stopped, so a program that dies in raw mode no longer leaves the terminal unusable.
- An interactive shell exits on SIGHUP at the prompt, hanging up its jobs, and ignores SIGTERM like bash instead of dying and losing its history. Background subshells no longer ignore SIGHUP and SIGTERM.
- History numbering in a session matches the saved file, so `!n` refers to the same command after a restart.
- The transient prompt left a stale line when the prompt and the command exactly filled the width of the terminal.
- Language versions in the prompt (node, python, rust, go) are looked up again after a change of directory or `PATH` and at least every 30 seconds, so `nvm use` or `pyenv local` show up.
- Ctrl-C on a line with an autosuggestion left the suggestion on screen, so it looked as if the whole command had run. The suggestion is cleared, `^C` is shown and `$?` is 130 like bash.

### Notes for the integrator

- Cargo.toml: rustyline is built with its optional `buffer-redux` feature (one extra crate, `buffer-redux`, MIT/Apache, whose only dependency `memchr` was already in the tree). Without it rustyline 15 throws away the bytes it has read past the end of a line when `readline` returns, which is the cause of the dropped burst/typeahead lines; there is no way around that from outside rustyline. If the extra crate is not acceptable, revert that one line in Cargo.toml and Cargo.lock; everything else still works, but lines typed ahead or pasted without bracketed paste are lost again. README's "depends on two crates" wording should then say "two direct dependencies".
- src/check.rs: drop the `("fc", "use history and !-expansion instead")` entry from the unsupported table; `fc` is a builtin now.
- README: line 275 "Ctrl-Z stops the foreground job" can add "and leaves a running loop"; list `fc` among the builtins (line 346); mention Alt-., Ctrl-E/End/Alt-F for suggestions, HISTSIZE/HISTFILESIZE/HISTFILE and the 50000 entry default, `^old^new` and word designators under history expansion. docs/grfsh.1: add `fc`, the new keys, the history variables, COLUMNS/LINES, and that interactive shells ignore SIGTERM and exit on SIGHUP.
