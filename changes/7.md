### Fixed

- Bytes 0x80 to 0xFF now stay single bytes. `printf '\xff'` writes ff and `printf '\xc3\xa9'`, `printf '\303\251'`, `%b` and `$'\xc3\xa9'` write é instead of mojibake. `read`, `mapfile`, command substitution, word splitting, here-documents, here-strings and pipes between builtins keep bytes exactly, so Latin-1 or binary data round-trips the way it does in bash.
- Scripts that are not valid UTF-8 run: Latin-1 comments and self-extracting installers (makeself, shar) with a binary payload after `exit` work. Scripts and sourced files are now read line by line as they run, like bash, so the part after `exit` is never read.
- Non-UTF-8 command-line arguments and environment variables no longer crash the shell (`export`, `export -p`), and their values are no longer empty inside the shell. Exported values reach programs byte for byte.
- File names that are not valid UTF-8 glob, display and open correctly, including with `cd`, `test`, redirections and `source`.
- `echo -e`, `printf` and `$'...'` decode every bash escape the same way bash does: `\0NNN` in `echo -e` and `%b`, `\NNN` in the format and `$'...'`, `\xHH`, `\uHHHH`, `\UHHHHHHHH`, `\e`, `\E`, `\cX` in `$'...'`, `\c` stopping output in `echo -e` and `%b`, `\"`, `\'` and `\?`. `printf` reports "missing hex digit" like bash, `%.Nb` truncates, and `$'...'` stops at a NUL byte. `$'...'` also works inside `${var/pattern/...}`, `${var%...}` and the other `${...}` operators.
- `printf %q`, `declare -p`, `export -p`, `set -x` traces and `cd` errors quote values with control characters or invalid bytes as `$'...'`, like bash. `declare -p` and `export -p` also escape `$` and backticks in double-quoted values.
- `read -n N` counts characters, not bytes, so a multibyte character is never split.
- `--json` no longer turns invalid UTF-8 output into Latin-1 characters: invalid bytes show as U+FFFD so the JSON stays valid, and plain `--agent` output keeps the original bytes.
- `--check` accepts files that are not valid UTF-8.
- `replace` and `write-file` keep bytes that are not UTF-8 instead of refusing the file.

### Design note (for ARCHITECTURE.md)

Strings stay `String` inside the shell. `src/bytes.rs` decodes external bytes losslessly: valid UTF-8 stays as is, and each byte that is not part of valid UTF-8 becomes one private-use code point (U+10FF80 to U+10FFFF, that is U+10FF00 plus the byte). A real U+10FF80..U+10FFFF character in the input is stored as its four raw bytes, so decoding and encoding always round-trip. `bytes::encode` turns those code points back into the raw bytes. Escape producers (`src/escapes.rs`, shared by `echo -e`, `printf` and `$'...'`) push bytes with `bytes::push_byte` and then call `bytes::canonical`, so a run of escaped bytes that forms valid UTF-8 becomes the real character and `${#x}` counts it as one, like bash in a UTF-8 locale. Every boundary converts: argv (`args_os`), the environment (`var_os`, `set_var` with `bytes::to_os`), script and sourced files (`bytes::LineReader`, which reads line by line on a descriptor at 255 or above, like bash), `read`, `mapfile`, command substitution, here-documents, file names (`bytes::from_os`, `bytes::to_path`), `exec` argv and `open` paths (`CString` from `bytes::encode`), builtin output (`bytes::Encoder` wraps standard output in `builtins::run`), error messages, table input and output, and agent output (`--json` uses `bytes::lossy`).
