### Added

- Name references: `declare -n`, `local -n` and `typeset -n`, including references to array elements (`declare -n r='arr[2]'`), references in `for` loops, `${!ref}` for the referenced name and `unset -n`.
- `set -a` and `set -o allexport` export every variable assigned while they are on, so `set -a; . ./.env; set +a` works.
- `export -f` exports functions to child shells in the bash format (`BASH_FUNC_name%%`), so child grfsh and bash processes can call them. `export -nf` and `unset -f` remove the export, and functions exported by bash are imported at startup.
- The `@A`, `@K`, `@k` and `@P` transforms, case modification with a pattern (`${v^^[aeiou]}`, `${v,,[A-M]}`) and the `~` and `~~` case toggles.
- `$BASH_LINENO`, and `$FUNCNAME` and `$BASH_SOURCE` follow functions and sourced files like bash in scripts and with `-c`.
- `declare +x`, `+i`, `+l`, `+u` and `+n` remove attributes, `export -n` unexports, `export -p` and `readonly -p` list in the bash format, and `unset -v` and `unset -n` are accepted.

### Fixed

- `a=1 b=$a` assigns left to right, so `b` is `1`; `a=1 b=$a cmd` gives the command `b=1` like bash, and `set -x` traces each assignment on its own line.
- `export NAME` before `NAME` has a value, and `declare -x NAME`, export the variable once it is assigned. `export -n NAME` keeps the value but stops exporting it.
- `IFS` is set to space, tab and newline at startup, so `old=$IFS; IFS=,; ...; IFS=$old` restores splitting.
- `"$*"` and `"${arr[*]}"` join with the first character of `IFS` (nothing when it is empty, a space when it is unset), also in `local IFS=,` functions and with `${!arr[*]}`, slices and substitutions. Unquoted `$*` and `$@` split each element separately.
- `"$@"` and `"${arr[@]}"` in assignments, `local`, here strings, `[[ ]]` and `case` words join the elements with spaces instead of keeping only the last one.
- `${!1}` and `${!#}` expand indirectly through positional parameters.
- `${arr[@]-default}`, `${arr[@]:-default}` and `${arr[@]+alt}` treat unset and empty arrays like bash.
- `$'\n'` and other `$'...'` strings work inside `${s//pattern/replacement}` and the other `${...}` operators.
- Tildes after `:` and after the first `=` in assignments are expanded (`PATH=~/bin:~/.local/bin`), also in `declare`, `export` and assignment-like arguments.
- Associative array keys with spaces or quotes (`h["key with space"]`, `${h['k']}`) work, an empty key is an error, and keys are listed in the same order as bash.
- `[[ -v arr[i] ]]`, `[[ -v assoc[key] ]]` and `test -v` with subscripts check the element.
- Assigning to a readonly variable stops the current command line, as in bash; `unset` of a readonly variable fails with status 1, and `read`, `for` and `export` of a readonly name fail with status 1.
- An assignment error such as an empty associative key stops the current command line instead of continuing.
- `a+=(x)` and `${#a[@]}` no longer copy the array, so 20,000 appends take 0.05 seconds instead of 5, and `mapfile` reads its input in blocks (100,000 lines in 0.01 seconds instead of 0.25).
- Large brace expansions such as `{1..200000}` expand fully; an expansion too large to fit in memory is an error instead of being left as text.
- `${#s}` and `${s:offset:length}` count bytes when `LC_ALL`, `LC_CTYPE` or `LANG` is `C` or `POSIX`.
- `declare -p` prints values with `$'...'` quoting when they contain control characters, escapes `$` and backquotes, quotes associative keys only when needed, adds bash's trailing space in associative arrays, and shows declared variables without a value as `declare -- name`.
- `local name` without a value leaves the variable unset inside the function, and `local` of an exported variable is restored in the environment when the function returns.
